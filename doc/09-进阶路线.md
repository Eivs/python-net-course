# 第 9 章：进阶路线（这套课之后往哪走）

本章做两件事：**说清这套课没讲什么**，以及**每个方向的第一步该怎么迈**。

诚实是前提：一套 19 课的实践材料不可能覆盖网络的全部。
下面每一节都标注了「本课讲到了什么程度」，避免你以为自己已经掌握。

---

## 一、自评表：这套课讲到了哪一层

| 主题 | 本课深度 | 说明 |
|---|---|---|
| IP / 子网 / 路由 | ✅ 能动手验证 | 掩码计算、最长前缀匹配、源地址选择 |
| DNS | ✅ 正向解析 + 手写报文 | 缓存、TTL、压缩指针；没讲 DNSSEC、DoH/DoT 实现 |
| TCP 握手/挥手/状态机 | ✅ 完整 | 状态能自己抓出来，异常类型能区分 |
| TCP 字节流与分帧 | ✅ 完整（重点） | 三种方案 + 健壮解码器 + 极端测试方法 |
| socket 选项 | ✅ 实测过常用的 | 没讲各平台差异细节、内核调优全貌 |

## 二、值得深入的十个方向

### 1. HTTP/2 与 HTTP/3

**先做什么**：用现成工具观察，而不是一上来读 RFC。

```bash
curl -v --http2 https://example.com/        # 看 ALPN 协商出 h2
openssl s_client -connect example.com:443 -alpn h2 -servername example.com
# 如果能装 nghttp2 工具: nghttp -nv https://example.com/  能看到帧序列
```

**要理解的核心问题**：为什么 HTTP/1.1 要做「6 个并行连接」？
HTTP/2 的 stream id 如何解决它？为什么 HTTP/2 仍有 TCP 层队头阻塞？
HTTP/3 的 QUIC 怎么做到「每条流独立丢包」？

**动手点**：在你的 `mini_http_server.py` 上实现一个最小的 HTTP/2 帧解析器
（只解析 SETTINGS 和 HEADERS 帧，不实现完整协议）—— 这一步的收获比读完 RFC 还大。

### 2. 拥塞控制

**先做什么**：意识到「TCP 帮你做了拥塞控制，但你不知道它怎么做的」，这已经和很多人不同了。

**要理解的核心问题**：慢启动为什么是指数增长？丢包为什么被当成拥塞信号（这是 CUBIC 时代的假设）？
BBR 为什么改用带宽和 RTT 建模？

**动手点**：在你的 echo 服务上，用真实网络（不是回环）传一个大文件，
同时用 `netstat -an | grep -c ESTABLISHED` 观察窗口变化；跨地域/走 VPN 的链路会看到明显差异。

### 3. 抓包与内核观测

**先做什么**：

```bash
sudo tcpdump -i en0 -n 'tcp port 443' -c 20      # 需要 root
```

**要理解的核心问题**：一次握手的每个包长什么样？seq/ack 如何递增？
重传和乱序在抓包里长什么样？

**替代方案（无 root 也能做很多事）**：本课全程用的 `netstat` / `lsof` / `sysctl` / `SO_ERROR`，
加上 Python 侧打印 `getsockopt`。想看内核统计可以关注 `netstat -s`（协议计数器，重传/丢包/错误都有）。

### 4. NAT、防火墙与内网穿透

**要理解的核心问题**：为什么家宽没有公网 IP 也能上网（NAT）？
为什么 P2P 需要打洞（STUN/TURN）？为什么 P2P 打洞不是 100% 成功（对称 NAT）？

**动手点**：本机的 `100.64/10`（CGNAT）地址就是现成案例（第 1、4 课）。
对比「直连内网 IP」「走网关 NAT 出公网」「走隧道网卡」三条路径的源 IP 变化。

### 5. IPv6

**先做什么**：

```bash
dig AAAA example.com
ping6 ::1
ifconfig en0 | grep inet6
```

**要理解的核心问题**：为什么 IPv6 没有 ARP（改用 NDP）？SLAAC 怎么无状态自动配置地址？
双栈环境下客户端怎么选（Happy Eyeballs）？

**动手点**：把第 1 课的 UDP 探测改成 `AF_INET6`，观察源地址是临时地址还是稳定地址。

### 6. TLS 的下一层

**要理解的核心问题**：TLS 1.3 为什么删掉了 RSA 密钥交换（前向安全）？
会话票据（session ticket）怎么实现 0-RTT？mTLS 双向认证在服务网格里怎么用？
证书吊销（OCSP/CRL）为什么工程上很难做对？

**动手点**：把第 18 课的本地 TLS 服务器改成**要求客户端证书**（`verify_mode=CERT_REQUIRED`
+ `load_verify_locations`），体验一次 mTLS 握手。

### 7. 高性能与异步

**先做什么**：理解第 19 课里事件循环「不能被阻塞」这条铁律。

**要理解的核心问题**：Python 的 GIL 对网络服务意味着什么（要开多进程）；
`asyncio` 的 `await` 在底层就是第 14 课的「非阻塞 + 事件循环」；
`SO_REUSEPORT` 多进程如何分摊连接。

**动手点**：把第 19 课的 `SelectorServer` 用 `asyncio` 重写一遍，
对比代码量、可读性和压测结果 —— 你会更清楚「框架帮你做了什么」。

### 8. 在 UDP 上自己实现可靠传输

这是把第 8~12 课全部打通的项目：**序号 + ACK + 重传 + 去重 + 窗口 + 拥塞控制**，
做完你就理解了 QUIC 为什么长成那样。

**最小可用版本**：发送方维护待确认队列 + 超时重传；接收方按序号去重、按序交付。
**验收标准**：人为丢包（发送端随机丢掉 20% 的包）后，接收端仍能收到完整且有序的数据。

### 9. 性能工程

**要用真实工具**，而不是本课的教学脚本：

| 工具 | 用途 |
|---|---|
| `wrk` / `hey` / `vegeta` | HTTP 压测（支持 keep-alive、并发、直方图） |
| `iperf3` | 纯带宽测试（排除应用层干扰） |
| `mtr` | traceroute + ping 的合体，看丢包分布在哪一跳 |
| `netstat -s` | 协议层计数器（重传、丢包、错误） |
| `perf` / 火焰图 | 应用层热点（注意 macos 上工具链不同） |

**指标纪律**：看 P50/**P99**/错误率/**QPS 曲线随并发变化的拐点**，而不是平均值。

### 10. 协议设计与演进

**要理解的核心问题**：
- 为什么所有协议都要留**版本字段**（第 9 课的 DNS 报文、HTTP 的 `HTTP/1.1`）；
- 为什么消息要有**长度上限**（第 12 课的 OOM 防护）；
- 为什么需要**幂等键**（第 17 课的重试）；
- 为什么错误码要分类（4xx/5xx 的语义差异直接决定能不能重试）。

**动手点**：给你的第 12 课解码器设计一个 v2 协议（增加字段），
并保证「新客户端能读旧服务器、旧客户端能读新服务器」—— 你会立刻体会到设计的取舍。

## 三、三个练手项目（按难度排序）

### 项目 A：TCP 代理（用第 11~13 课）

**需求**：监听一个端口，把流量转发到后端；支持并发连接；`SIGINT` 优雅退出；
打印每条连接的字节数、耗时、关闭原因（谁先关、是否 RST）。

**为什么值得做**：你会被迫处理「双向同时收发的字节流」——比 echo 服务难一个量级。
本课的 `demo_11`/`demo_13` 给了所有需要的基础。

### 项目 B：带缓存的 HTTP 反向代理（用第 15~17、19 课）

**需求**：接收客户端请求 → 转发到后端 → 缓存响应（尊重 `Cache-Control`/`ETag`）→
回给客户端时支持 `If-None-Match` → 到后端的连接要复用（连接池）。

**为什么值得做**：这是真实世界里最有价值的一类程序（nginx/Varnish/Envoy 的核心），
而且它把「HTTP 语义 + 连接复用 + 并发模型」三件事压在一起。

### 项目 C：迷你可靠 UDP 传输（用第 8~12 课）

见上文第 8 点。做完它，你再看 QUIC 的文档会觉得「这只是把我知道的东西标准化了」。

## 四、资料清单（都是可以核实来源的）

**规范（挑需要的看，不要通读）**

| 编号 | 内容 |
|---|---|
| RFC 791 / 793 / 768 | IP / TCP / UDP 的原始定义（短，值得翻） |
| RFC 1035 | DNS（本课第 9 课就是它的最小实现） |
| RFC 7230~7235 | HTTP/1.1（报文、语义、缓存、条件请求、Range） |
| RFC 7540 / 7541 | HTTP/2 与 HPACK |
| RFC 9000 / 9001 / 9002 / 9114 | QUIC 与 HTTP/3 |
| RFC 8446 | TLS 1.3 |
| RFC 9293 | TCP 的现行标准（把 793 加勘误和补充整理过） |

**书**

- Stevens《TCP/IP Illustrated, Volume 1》—— 协议层面的经典，配抓包一起看最好；
- Stevens《UNIX Network Programming, Volume 1》—— socket API 的权威，第 11~14 课的内容在这里有更深的展开；
- Kurose & Ross《Computer Networking: A Top-Down Approach》—— 教材式系统学习；
- Grigorik《High Performance Browser Networking》—— 网络性能视角（含 HTTP/2、TLS、移动网络）。

**工具**

`wireshark` / `tcpdump`（抓包）、`mtr`（路径丢包）、`curl`（HTTP 全功能）、
`openssl s_client`（TLS 排障）、`hey` / `wrk` / `vegeta`（压测）、
`mitmproxy`（中间人调试）、`nghttp2`（HTTP/2 调试）、`netstat -s`（协议计数器）。

## 五、从「看得懂」到「写得对」的三步

```
第 1 步（本课已完成）：能被真实数据说服
    → 知道 BrokenPipe 不等于对方收到、TIME_WAIT 属于主动关闭方、
      MTU 1500 推出 MSS 1460、CLOSE_WAIT 是代码 bug。

第 2 步：能在写代码前预判问题
    → 设计一个自定义协议时，第一反应是「边界怎么划、长度上限是多少、版本字段放哪」；
      写客户端时第一反应是「三个超时怎么设、要不要重试、幂等吗」。

第 3 步：能在故障现场用证据说话
    → 不再说「网络问题」，而是说「对端 443 端口没有监听（RST 0.6ms 返回）」；
      不再说「偶尔慢」，而是说「P99 的 40ms 尖刺与 Nagle+延迟确认吻合」。
```

**检验标准**：找一次真实的故障（或自己制造一个），
用第 8 章的排障手册走一遍，把每一步的**命令 + 输出**记下来 ——
如果你能在 10 分钟内定位到「是哪一层的问题」，这套课就真正学完了。

## 六、最后：这套课最想留下的三句话

1. **边界是应用层的事**。TCP 给你字节流，UDP 给你数据报，两者都不给你「消息」。
   协议设计的第一个问题永远是「对方怎么知道一条消息结束了」。

2. **可靠性和延迟是花钱买的**。握手、ACK、重传、TLS、连接池 —— 每一项都在用延迟或复杂度
   换某种保证。知道自己在为什么付费，是工程判断力的开始。

3. **状态是排障的通用语言**。`LISTEN` / `ESTABLISHED` / `TIME_WAIT` / `CLOSE_WAIT` / `SYN_SENT`
   这五个词，配上「拒绝 vs 超时」的区分，能解决你遇到的绝大多数网络问题。
   剩下的，才需要抓包和读内核源码。
