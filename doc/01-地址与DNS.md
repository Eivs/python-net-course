## 第 1 课：IP 地址到底是什么

**一句话**：IPv4 地址是一个 32 位无符号整数；`192.168.1.10` 只是它的「点分十进制」写法。

### 【原理】三种表示法是同一个东西

```
字符串      192  .  168  .   1   .  10
二进制    11000000 10101000 00000001 00001010
整数                  3232235786  (0xC0A8010A)
字节序    大端：C0 A8 01 0A   ← 网线上真正传输的 4 个字节
```

**为什么必须是「大端」**：x86/ARM 在内存里存整数用的是小端（低位字节放低地址），
而网络协议统一规定用大端（网络字节序）。所以整数在发给网线之前必须转换，
否则对端解出来是错的。Python 里 `socket.htons()` / `struct.pack("!H")` 都在做这件事。

**一个 IP 里藏着「网络号 + 主机号」**：由掩码（或前缀长度 `/23`）划分。
同网段可以二层直达（ARP 问一下 MAC 就行），不同网段必须交给网关。

### 【代码要点】

```python
# 手工把点分十进制拼成整数：每段 8 位，第 1 段是最高 8 位
octets = [int(part) for part in text.split(".")]
as_int = 0
for value in octets:
    as_int = (as_int << 8) | value        # <<8 左移一个字节，再或上新的低 8 位

# 用标准库验证：inet_aton 产出的就是网线上的 4 个字节
packed = socket.inet_aton(text)           # b'\xc0\xa8\x01\n'
struct.unpack("!I", packed)[0]            # ! = 大端, I = 32 位无符号
```

### 【实测】`01_address_dns/demo_01_ip_address.py`

```text
点分十进制        : 192.168.1.10
四段（二进制）    : ['11000000', '10101000', '00000001', '00001010']
手工拼成整数      : 3232235786  = 0xC0A8010A  = 0b11000000101010000000000100001010
socket.inet_aton('192.168.1.10') = b'\xc0\xa8\x01\n'  即每个字节: [192, 168, 1, 10]
三种算法结果一致 -> 证明所谓 IP 地址就是一个整数。
socket.htons(0x1234) = 0x3412   (把 16 位整数转成网络序, 端口号会用到)
```

注意 `0x1234 → 0x3412`：两个字节对调了，这就是字节序转换的直观样子。

**子网划分实测**（用一个通用例子 `192.168.1.10/24` 演示；换成你 `ifconfig` 里的「inet 地址 + netmask」结果一样）：

```text

网络地址          : 192.168.1.0   (主机位全 0, 代表整个网段)

反掩码 wildcard   : 0.0.0.255

地址总数          : 256   可用主机数: 254
前 3 个可用主机   : ['192.168.1.1', '192.168.1.2', '192.168.1.3']
前缀长度          : /24  -> 前 24 位是网络号, 后 8 位是主机号
  192.168.1.1     和本机同网段? True   同网段内的网关
  192.168.2.1     和本机同网段? False  网络号变了, 属于别的网段
  8.8.8.8         和本机同网段? False  公网地址, 完全不同网段
```

**探测本机出口 IP 的技巧**（UDP `connect()` 不发包，只让内核查一次路由表）：

```python

probe.connect(("1.1.1.1", 80))       # 不产生任何流量

```

（本段已泛化：把本机内网 IP 写成了 `<本机内网 IP>`，源端口保留原值。）

打公网和打 `127.0.0.1` 得到的源 IP 不同，说明**回环走的是完全独立的路径**（不出网卡）。
源端口是内核随机分配的临时端口 —— 第 5 课的主角。

### 【坑】

- 用 `len(str)` 算「字节数」是经典 bug；中文一个字 3 字节（UTF-8），要 `len(s.encode())`。
- `0.0.0.0` 不是「某个地址」，而是 bind 时的「所有网卡」通配语义（第 5 课详述）。
- 别自己写正则校验 IP：`ipaddress.ip_address()` / `ip_network()` 才是正解，它还顺便告诉你
  `is_private` / `is_loopback` / `is_link_local`。

## 第 2 课：域名怎么变成 IP（DNS）

**一句话**：DNS 是一个全球分布式的「域名 → IP」查询系统，默认跑在 UDP/53；
它把解析结果缓存起来，缓存时长由 TTL 决定。

### 【原理】一次解析的完整路径

```
浏览器
  └─ 1. /etc/hosts            （本地覆盖，改这里能「劫持」域名，开发常用）
  └─ 2. 系统解析器缓存         （macOS 由 mDNSResponder 管）
  └─ 3. 本地 DNS 服务器（递归查询，跨半个地球去问权威服务器）
  └─ 4. 各级缓存（TTL 内直接用）
```

解析顺序里最关键的一条：**hosts 文件优先于 DNS**。这就是本地调试改 hosts 能生效的原因。

```text
/etc/hosts 内容里非注释的部分（解析顺序: hosts 文件 -> DNS）:
  0.0.0.0         <你机器的主机名>.local
  127.0.0.1       <你机器的主机名>.local
  127.0.0.1       localhost.<某个代理工具>.com
  127.0.0.1       localhost
  255.255.255.255 broadcasthost
  ...（共 N 条, 上面只显示前 10 条;其中 M 条指向本机回环（典型的「本地劫持」））
      想看全部: grep -v '^#' /etc/hosts
```

（本段已脱敏：上面是本机条目的**结构示例**，主机名与内部域名换成了占位符；
真实条目往往还包括本地开发服务、代理工具、公司内网域名的配置。）

（上面省略了中间几行，完整 10 行在 `.logs/demo_02_dns_lookup.log` 里；日志属于你自己机器的输出，`doc/` 里做了脱敏。
本机 hosts 可能有几百条非注释条目，**全打出来会盖住重点，所以脚本只取前 10 行**。）

这张表值得看的原因：里面通常有**相当一部分条目指向回环**（本地开发服务、代理工具、
内部域名…），它们优先级高于 DNS。所以「为什么我的请求没走到线上」经常答案就在这张表里——
排查任何「本地/某些人正常、线上/其他人不正常」的问题，先看一眼自己的 hosts。

### 【代码要点】

```python
# 唯一推荐的入口：一次给你 IPv4 + IPv6 + 所有可用走法
for family, socktype, proto, canonname, sockaddr in socket.getaddrinfo(host, 80, proto=socket.IPPROTO_TCP):
    ...
# 老 API（不要在新代码里用）：只返回一个 IPv4、忽略 IPv6、错误都抛同一个 gaierror
socket.gethostbyname(host)
```

### 【实测】`01_address_dns/demo_02_dns_lookup.py`

```text
getaddrinfo('example.com', 80, proto=TCP) 共 4 条:
  IPv4  TCP流   proto=6   规范名=-            sockaddr=('172.66.147.243', 80)
  IPv4  TCP流   proto=6   规范名=-            sockaddr=('104.20.23.154', 80)
  IPv6  TCP流   proto=6   规范名=-            sockaddr=('2606:4700:10::ac42:93f3', 80, 0, 0)
  IPv6  TCP流   proto=6   规范名=-            sockaddr=('2606:4700:10::6814:179a', 80, 0, 0)
  注意 sockaddr 是元组, 不是字符串:
```

这是写 IPv6 兼容代码最容易踩的地方：**IPv4 的 `sockaddr` 是 `(ip, port)`，IPv6 是 4 元组
`(ip, port, flowinfo, scopeid)`**，把返回值按二元组统一解包在 IPv6 环境必崩。

**一个域名多个 IP 是常态**（CDN / 负载均衡 / 故障转移）：

```text
  example.com
    A   记录 (IPv4): 2 个 ['104.20.23.154', '172.66.147.243']
    AAAA记录 (IPv6): 2 个 ['2606:4700:10::6814:179a', '2606:4700:10::ac42:93f3']
  www.baidu.com
    A   记录 (IPv4): 2 个 ['153.3.238.127', '153.3.238.28']
    AAAA记录 (IPv6): 2 个 ['2408:873d:22:18cb:0:ff:b037:e6d8', '2408:873d:22:1a91:0:ff:b013:cf81']
  one.one.one.one
    A   记录 (IPv4): 2 个 ['1.0.0.1', '1.1.1.1']
    AAAA记录 (IPv6): 2 个 ['2606:4700:4700::1001', '2606:4700:4700::1111']
```

**缓存的效果——第一次和第二次差 30 倍**：

```text
  第 1 次解析 www.wikipedia.org:  51.900 ms
  第 2 次解析 www.wikipedia.org:   1.609 ms
  第 3 次解析 www.wikipedia.org:   2.456 ms
  第 4 次解析 www.wikipedia.org:   2.015 ms
```

这就是「首次请求慢常常是 DNS 冷缓存，而不是带宽问题」的来源。

**我的机器到底在用哪台 DNS 服务器**（`scutil --dns` 的解析结果）：

```text
  nameserver[0] : <隧道/VPN 网卡下发的 DNS>
  nameserver[1] : <同一个 DNS 的 IPv6 地址>
  nameserver[0] : <物理网卡拿到的 DNS>
```

（本段已脱敏：本机实际使用的 DNS 服务器地址换成了占位符。）

看到地址落在 CGNAT 段（`100.64.0.0/10`）或者 `if_index` 挂在某张隧道网卡上，就说明
**有 VPN / 组网工具抢占了部分域名的解析权**（分流 DNS）。
企业网里这直接决定你能访问哪些内网域名——「改了 DNS 才能连内网」的根源。

### 【坑】

- `socket.getaddrinfo` 返回的 `sockaddr` 是元组不是字符串；IPv6 元组有 4 个元素。
  写死了 `(ip, port)` 解包的代码在 IPv6 环境必崩。
- DNS 解析失败和「域名不存在」是两件事（`gaierror` 里包含原因），但很多库把它们糊成一个异常。
- TTL 决定「改解析多久全网生效」：上线前把 TTL 调小是运维常规操作。

### 【练习】

`python3 demo_02_dns_lookup.py github.com`，对比不同域名的 A/AAAA 记录数量与耗时。

## 第 3 课：我的机器有几张网卡（链路层）

**一句话**：真正收发数据的是网卡；它有 MAC（链路层）和 IP（网络层）两个身份，
IP→MAC 的翻译叫 ARP。

### 【原理】MTU 与 MSS 的关系（这是后面「粘包」的物理根源）

```
以太网 MTU                1500 字节   ← 一个以太网帧能装的 IP 包上限
  - IPv4 头（无选项）        20
  - TCP 头（无选项）         20
  = TCP MSS               1460 字节   ← 对端一次最多发这么多 TCP 载荷
```

所以应用层 `send(10240)` 会被内核切成 `ceil(10240/1460) = 8` 个报文段发出去。

### 【实测】`01_address_dns/demo_03_local_interfaces.py`

```text
  [lo0]  up=True  mtu=16384  status=-
    标志位: UP,LOOPBACK,RUNNING,MULTICAST
    MAC  : (无, 可能是虚拟/回环网卡)
    IPv4 : 127.0.0.1        掩码=0xff000000(/8)       广播=-
    IPv6 : ::1                                        /128 (回环, scope=-)

  [en0]  up=True  mtu=1500  status=active
    MAC  : 00:1a:2b:3c:4d:5e
    IPv4 : 192.168.1.10    掩码=0xffffff00(/24)      广播=192.168.1.255
```

（本段已泛化：MAC 与内网地址换成了通用示例；不同机器会打印出各自真实的值。）

识别网卡的经验（一台机器可能同时有 30+ 张）：

| 名字 | 是什么 |
|---|---|
| `lo0` | 回环，MTU 16384（本机通讯不用真发） |
| `en0` | 物理网卡（Mac 上通常是 Wi-Fi 或有线） |
| `utunN` | VPN / 隧道（Tailscale、WireGuard、企业 VPN） |
| `bridgeN` | 虚拟交换机（虚拟机 / Docker） |
| `awdl0`/`llw0` | AirDrop 之类系统服务用的虚拟网卡 |

**ARP 缓存**（IP → MAC 的邻居缓存）能直接看到，而且能把默认网关那条挑出来：

```text
  默认网关 = 192.168.1.1
  网关在 ARP 缓存里: ? (192.168.1.1) at 00:1a:2b:3c:4d:5f on en0 ifscope [ethernet]
  当前 ARP 表前 6 条（共 23 条）:
  ? (192.168.1.37) at 00:1a:2b:3c:4d:60 on en0 ifscope [ethernet]
  ? (192.168.1.44) at 00:1a:2b:3c:4d:61 on en0 ifscope [ethernet]
  ? (192.168.1.116) at 00:1a:2b:3c:4d:62 on en0 ifscope [ethernet]
```

（本段已泛化：内网 IP 与 MAC 换成了通用示例；ARP 条目数随局域网设备多少而变。）

发第一个包之前必须先「喊一声」：谁是 192.168.1.1？拿到 MAC 才构造以太网帧。
ARP 表里有多少条，顺带就告诉你这个子网里有多少活跃设备。

### 【坑】

- 一个网卡可以有多个 IP，所以「本机 IP」这种说法本身不严谨；要问「去哪张网卡的路」。
- 隧道网卡 MTU 更小（常见 1280/1400），会让有效 MSS 变小——这是「VPN 一开就变慢」的常见原因。
- 「同网段」判断错误会导致代码去 ping 网关却以为在打内网。用 `ipaddress.ip_address(x) in net`。

### 【练习】

找一张 MTU ≠ 1500 的网卡（`ifconfig | grep mtu`），按第 3 课的公式算它的 MSS。

## 第 4 课：内核怎么决定包从哪张网卡出去

**一句话**：查路由表，规则是**最长前缀匹配**；由出口网卡决定源 IP，下一跳决定 MAC。

### 【原理】内核处理 `connect("1.1.1.1", 443)` 的四步

```
1) 查路由表 → 最长前缀匹配 → 得出出口网卡 + 下一跳网关
2) 用出口网卡的 IP 作为源地址
3) 下一跳不是直连 → 用 ARP 找网关的 MAC，把包交给它
4) 每一跳路由器重复这个过程（TTL 每跳 -1，减到 0 就丢弃并回 ICMP 超时）
```

### 【实测】`01_address_dns/demo_04_routing_table.py`

```text
    Destination        Gateway            Flags               Netif Expire
    default            192.168.1.1        UGScg                 en0
    default            link#28            UCSIg           bridge100      !
    default            link#35            UCSIg              utun10
```

（本段已泛化：内网地址换成通用示例。注意这里出现了**三条 default**，下一节会解释。）

不过 30+ 张网卡的机器上直接 dump 路由表会淹死重点，所以脚本会**把与「我的流量」有关的路由单独挑出来**：

```text
  只看与「我的流量」有关的路由（本机出口 IP = <本机内网 IP>）:
    [关键路由    ] default              网关=192.168.1.1         标志=UGScg   出口=en0
    [关键路由    ] default              网关=link#28            标志=UCSIg   出口=bridge100
    [关键路由    ] default              网关=link#35            标志=UCSIg   出口=utun10
    [关键路由    ] 127                  网关=127.0.0.1          标志=UCS     出口=lo0
    [关键路由    ] 127.0.0.1            网关=127.0.0.1          标志=UH      出口=lo0
    [命中本机的路由 ] <本机 IP>/32        网关=link#14            标志=UCS     出口=en0
    [命中本机的路由 ] <本机 IP>           网关=00:1a:2b:3c:4d:5e  标志=UHLWI   出口=lo0
```

（本段已泛化：内网地址与 MAC 换成通用示例；真实运行时这里会打印出你自己机器的地址。）

这张表把本机选路的全貌说清楚了：

- 三条 `default`（物理网卡 / 虚拟机网桥 / VPN 隧道）：去公网时到底走哪条，由优先级决定；
- `127` 与 `127.0.0.1`（`UH` = 主机路由）：回环专用；
- `<本机 IP>/32` 走物理网卡（`en0`），同时还有一条 `UHLWI` 的 `lo0` 克隆条目（内核为「我自己」保留的）。

**这台机器有三条默认路由**（物理网卡 + 虚拟机网桥 + VPN 隧道）——
「VPN 一开某些站点就访问不了」的原因就在这里：流量被更高优先级的隧道抢走了。

**实测源 IP 的选择**：

```text
  目标 127.0.0.1        源 IP 127.0.0.1        源端口 49601  回环地址
  目标 192.168.1.1      源 IP <本机内网 IP>    源端口 64290  本网段的默认网关（直连）
  目标 1.1.1.1          源 IP <本机内网 IP>    源端口 56582  公网（走默认路由）
  目标 192.0.2.1        源 IP <本机内网 IP>    源端口 56202  TEST-NET-1, 保留地址
```

（本段已泛化：本机内网 IP 换成占位符；三行“打公网”的源 IP 相同，这说明它们都走了同一张网卡。）

**最长前缀匹配**（本机命中的是 `/32` 主机路由，而不是 `default`）：

```text
  /32  <本机 IP>/32     出口 en0    网关列=link#14          标志=UCS
  /32  <本机 IP>/32     出口 lo0    网关列=00:1a:2b:3c:4d:5e 标志=UHLWI
  -> 胜出的是 /32 的本机地址, 出口网卡 en0
```

（本段已泛化：本机地址与 MAC 换成占位符。）

**TTL 逐跳递减（traceroute 能看到真实路径）**：

```text
  1  192.168.1.1    29.651 ms     ← 本地路由器的内网口
  2  192.168.2.1    108.726 ms    ← 上一级接入设备
  3  203.0.113.9    4.670 ms      ← 进入城域网（203.0.113.x 是文档专用网段）
  4  *                            ← 很多路由器不回 ICMP，这是正常现象
  5  *
  6  *
```

（本段已泛化：路由器地址换成通用示例；真实输出里是运营商的实际地址。
如果本机没有 traceroute 或它被策略挡住，脚本会跳过这段并印一句说明。）

排障价值：一眼分辨「慢在本地、慢在上游、还是慢在对方」。

### 【坑】

- 明细路由（`/32`/`/24`）永远赢过 `default`；想局部改流量就加一条明细路由，别动默认路由。
- `traceroute` 里出现 `*` 不等于断了，只是那一跳不回 ICMP。
- 改路由/加网卡（VPN）之后，之前缓存的 ARP 和建立的连接不会自动跟着走。

### 【练习】

把 `demo_04` 里的 traceroute 目标换成 `8.8.8.8`，对比两条路径（很可能一条走 VPN）。

## 本章小结

| 结论 | 验证方式 |
|---|---|
| IP = 32 位整数，传输用大端 | 手工移位 + `inet_aton` + `ipaddress` 三方对照 |
| 地址 = 网络号 + 主机号，掩码切分 | `/23` 算出 512 个地址、广播地址 |
| 回环不走网卡 | 同一个调用打 `1.1.1.1` 和 `127.0.0.1` 得到不同源 IP |
| DNS 有 hosts / 系统 / 服务器三层缓存 | 同一域名连续解析，51.9ms → 1.6ms |
| MTU 1500 → MSS 1460 | 从 `ifconfig` 的 MTU 直接算，代码里用 `ceil(payload/MSS)` 验证分片数 |
| 路由是最长前缀匹配 | 打印命中本机地址的所有路由并按前缀长度排序 |
| TTL 换来了 traceroute | 真实抓到 5 跳路由器 IP |
